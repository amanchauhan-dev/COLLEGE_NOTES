## Q.1 (c) Explain the lifecycle of Android Activity with suitable diagram. [07]

=> **Activity lifecycle** is the set of states through which an Activity passes from creation to destruction.

=> Android calls lifecycle callback methods automatically when the Activity changes state.

### Activity lifecycle diagram

```text
Activity launched
      |
      v
  onCreate()
      |
      v
  onStart()
      |
      v
  onResume()
      |
      v
Activity running
      |
      v
  onPause()
   /      \
  v        v
onResume() onStop()
             |
             v
        onRestart()
             |
             v
          onStart()
             |
             v
          onResume()

Finish activity:
onPause() -> onStop() -> onDestroy()
```

### Lifecycle methods

1. **onCreate()**

=> Called when the Activity is first created.

=> Used to initialize variables and set the layout using `setContentView()`.

2. **onStart()**

=> Called when the Activity becomes visible to the user.

3. **onResume()**

=> Called when the Activity starts interacting with the user.

4. **onPause()**

=> Called when the Activity loses focus.

=> Used to pause animations, camera preview or other temporary work.

5. **onStop()**

=> Called when the Activity is no longer visible.

6. **onRestart()**

=> Called when a stopped Activity is started again.

7. **onDestroy()**

=> Called before the Activity is destroyed.

### Example

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
    }

    @Override
    protected void onStart() {
        super.onStart();
    }

    @Override
    protected void onResume() {
        super.onResume();
    }

    @Override
    protected void onPause() {
        super.onPause();
    }

    @Override
    protected void onStop() {
        super.onStop();
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
    }
}
```

## Q.2 (b) Discuss types of Intent to link Android activities. [04]

=> Intent is commonly used to link one Activity with another Activity.

### Types of Intent

1. **Explicit Intent**

=> Explicit Intent directly specifies the target Activity class.

=> It is used when the target component is known.

```java
Intent intent = new Intent(MainActivity.this, SecondActivity.class);
startActivity(intent);
```

=> Passing data:

```java
Intent intent = new Intent(MainActivity.this, SecondActivity.class);
intent.putExtra("username", "Aman");
startActivity(intent);
```

2. **Implicit Intent**

=> Implicit Intent does not specify the target component. It specifies only the action.

=> Android finds a suitable application to complete the action.

```java
Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://www.google.com"));
startActivity(intent);
```

### Difference

| Explicit Intent | Implicit Intent |
|---|---|
| Target component is specified. | Target component is not specified. |
| Mostly used inside same app. | Used to call system or other apps. |
| Example: Open `SecondActivity`. | Example: Open browser or dialer. |

## Q.2 (c) Explain detail architecture of Android with suitable block diagram. [07]

=> Android architecture is a software stack made of different layers.

### Block diagram

```text
+----------------------------------+
|          Applications             |
| Contacts, Phone, Browser, Apps    |
+----------------------------------+
|      Application Framework        |
| Activity Manager, View System,    |
| Content Providers, Resource       |
| Manager, Notification Manager     |
+----------------------------------+
|  Android Runtime + Native Libs    |
| DVM/ART, Core Libraries, SQLite,  |
| WebKit, OpenGL ES, Media Libs     |
+----------------------------------+
|            Linux Kernel           |
| Drivers, Memory, Process, Power,  |
| Security, Network Stack           |
+----------------------------------+
```

### Layers

1. **Linux Kernel**

=> It is the bottom layer of Android architecture.

=> It provides device drivers, memory management, process management, security, networking and power management.

2. **Native Libraries**

=> These libraries are written in C/C++.

=> Examples: SQLite for database, WebKit for browser, OpenGL ES for graphics, media libraries for audio/video.

3. **Android Runtime**

=> It contains core Java libraries and runtime environment.

=> Older Android used Dalvik Virtual Machine, while newer Android uses ART.

=> It executes Android application bytecode.

4. **Application Framework**

=> Provides high-level services used by applications.

=> Important managers include Activity Manager, Resource Manager, Content Providers, View System and Notification Manager.

5. **Application Layer**

=> Top layer containing system apps and user-installed apps.

=> Examples: Phone, SMS, Contacts, Browser, Camera and third-party apps.

## Q.2 (c) OR What is Intent? How are they used to Broadcast and Receive Events? [07]

=> **Intent** is a messaging object used to communicate between Android components.

=> It can be used to start activities, start services and deliver broadcasts.

### Intent for broadcasting events

=> A broadcast is a message sent by the Android system or an application.

=> The message is sent using an Intent.

=> Broadcasts are received by Broadcast Receivers.

### Sending a broadcast

```java
Intent intent = new Intent("com.example.MY_EVENT");
intent.putExtra("message", "Hello Receiver");
sendBroadcast(intent);
```

### Receiving a broadcast

```java
public class MyReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {
        String msg = intent.getStringExtra("message");
        Toast.makeText(context, msg, Toast.LENGTH_SHORT).show();
    }
}
```

### Register receiver in manifest

```xml
<receiver android:name=".MyReceiver">
    <intent-filter>
        <action android:name="com.example.MY_EVENT" />
    </intent-filter>
</receiver>
```

### Common system broadcasts

1. Battery low.
2. Boot completed.
3. Network changed.
4. Airplane mode changed.
5. Power connected or disconnected.

### Uses

1. Notify apps about system events.
2. Communicate between app components.
3. Start work when a specific event occurs.
4. Receive messages even when Activity is not running.

## Q.3 (c) Define Data Storage. List all data storage options. [07]

=> **Data Storage** means saving application data permanently or temporarily so that it can be used later.

=> Android provides different storage options depending on the type and size of data.

### Data storage options in Android

1. **SharedPreferences**

=> Used to store small key-value pairs.

=> Example: login status, username, settings.

```java
SharedPreferences sp = getSharedPreferences("MyPrefs", MODE_PRIVATE);
sp.edit().putString("name", "Aman").apply();
```

2. **Internal Storage**

=> Stores private files in app-specific internal memory.

=> Other apps cannot access these files.

=> Files are removed when the app is uninstalled.

3. **External Storage**

=> Stores files on shared storage such as SD card or public storage.

=> Useful for images, videos, documents and downloaded files.

=> Permissions may be required depending on Android version and file location.

4. **SQLite Database**

=> Used for structured relational data.

=> Useful for records such as students, contacts, notes and transactions.

5. **Content Provider**

=> Used to share data between applications in a secure way.

=> Example: Contacts provider.

6. **Network/Cloud Storage**

=> Data can be stored on a remote server using web APIs.

=> Useful when data should be synced across devices.

### Choosing storage

| Requirement | Suitable option |
|---|---|
| Small settings | SharedPreferences |
| Private files | Internal Storage |
| Public media/files | External Storage |
| Structured records | SQLite |
| Share data with apps | Content Provider |
| Sync online | Network/Cloud |

## Q.3 (a) OR What is the use of `<permission>` tag? Where permission can be enforced? [03]

=> The `<permission>` tag is used in `AndroidManifest.xml` to define a custom permission for an application.

=> Custom permissions protect application components from unauthorized access by other applications.

### Example

```xml
<permission
    android:name="com.example.myapp.MY_PERMISSION"
    android:protectionLevel="normal" />
```

=> Another application must request this permission using:

```xml
<uses-permission android:name="com.example.myapp.MY_PERMISSION" />
```

### Permission can be enforced at

1. **Activity level**

=> Protects an Activity from being started by unauthorized apps.

2. **Service level**

=> Protects a Service from being started or bound by unauthorized apps.

3. **Broadcast Receiver level**

=> Protects receiver from unauthorized broadcasts.

4. **Content Provider level**

=> Protects data access for query, insert, update and delete operations.

5. **Code level**

=> Permission can also be checked programmatically using methods like `checkCallingPermission()`.

## Q.3 (c) OR Write detailed note on different types of layouts. [07]

=> Layouts are ViewGroups used to arrange UI controls on the screen.

### Types of layouts

1. **LinearLayout**

=> Arranges child views in a single direction, either vertical or horizontal.

```xml
<LinearLayout
    android:orientation="vertical"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

2. **RelativeLayout**

=> Places child views relative to parent or other views.

```xml
<RelativeLayout
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

3. **FrameLayout**

=> Displays a single view or stacks child views on top of each other.

=> Commonly used for fragment containers.

```xml
<FrameLayout
    android:id="@+id/container"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

4. **TableLayout**

=> Arranges views in rows and columns using `TableRow`.

```xml
<TableLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content">
    <TableRow>
        <TextView android:text="Name" />
        <EditText android:hint="Enter Name" />
    </TableRow>
</TableLayout>
```

5. **AbsoluteLayout**

=> Places views at exact x and y coordinates.

=> It is not recommended because it does not adjust well to different screen sizes.

6. **ConstraintLayout**

=> Modern flexible layout that positions views using constraints.

=> It reduces nested layouts and supports responsive design.

7. **GridLayout**

=> Arranges child views in rows and columns like a grid.

### Conclusion

=> Layouts define the visual structure of an Android screen and help create responsive user interfaces.

## Q.4 (c) Which steps are required for publishing an Android application? [07]

=> Publishing means preparing, signing and distributing an Android application to users.

### Steps

1. **Complete application development**

=> Finish coding, UI design, testing and bug fixing.

2. **Set package and version**

=> Set unique package name, `versionCode` and `versionName`.

3. **Test application**

=> Test on emulator and real devices with different screen sizes and Android versions.

4. **Prepare release build**

=> Remove debug logs, test keys and unnecessary files.

5. **Sign the application**

=> Android applications must be digitally signed before installation or publishing.

=> Generate signed APK or Android App Bundle from Android Studio.

6. **Create Play Console account**

=> Register as a Google Play developer.

7. **Create store listing**

=> Add app name, description, screenshots, app icon, feature graphic, category and contact details.

8. **Content rating and privacy**

=> Complete content rating, target audience, data safety and privacy policy details.

9. **Set pricing and distribution**

=> Select free/paid app and choose countries.

10. **Upload APK/AAB**

=> Upload the signed release file to Play Console.

11. **Submit for review**

=> Google reviews the application. After approval, the application is published on Play Store.

## Q.4 (c) OR What is use of MediaPlayer class? Briefly explain methods of it. [07]

=> **MediaPlayer** is an Android class used to play audio and video files.

=> It can play media from `res/raw`, local files, content providers or network URLs.

### Uses

1. Play music.
2. Play video sound.
3. Stream audio from internet.
4. Pause, stop and resume playback.

### Important methods

1. **create()**

=> Creates and initializes MediaPlayer for a resource.

```java
MediaPlayer mediaPlayer = MediaPlayer.create(this, R.raw.song);
```

2. **setDataSource()**

=> Sets media source from file path, URI or URL.

3. **prepare()**

=> Prepares the player for playback.

4. **start()**

=> Starts or resumes playback.

5. **pause()**

=> Pauses currently playing media.

6. **stop()**

=> Stops playback.

7. **seekTo()**

=> Moves playback to a specific position.

8. **isPlaying()**

=> Checks whether media is currently playing.

9. **release()**

=> Releases MediaPlayer resources.

### Example

```java
MediaPlayer mediaPlayer = MediaPlayer.create(this, R.raw.song);

btnPlay.setOnClickListener(v -> mediaPlayer.start());

btnPause.setOnClickListener(v -> {
    if (mediaPlayer.isPlaying()) {
        mediaPlayer.pause();
    }
});

btnStop.setOnClickListener(v -> {
    mediaPlayer.stop();
    mediaPlayer.release();
});
```

=> It is important to call `release()` when playback is finished to free system resources.

```java
public class DrawingView extends View {

    public DrawingView(Context context) {
        super(context);
        paint.setColor(Color.RED);
        paint.setStrokeWidth(6);
        paint.setTextSize(40);
    }

    @Override
    protected void onDraw(Canvas canvas) {
        super.onDraw(canvas);

        canvas.drawLine(50, 50, 300, 50, paint);
        canvas.drawRect(50, 100, 300, 250, paint);
        canvas.drawCircle(180, 400, 80, paint);
        canvas.drawText("2D Graphics", 50, 550, paint);
    }
}
```

Use custom view in Activity:

```java
setContentView(new DrawingView(this));
```

3. **Using Bitmap**

=> Bitmap is used to draw or manipulate images pixel by pixel.

```java
Bitmap bitmap = BitmapFactory.decodeResource(getResources(), R.drawable.logo);
canvas.drawBitmap(bitmap, 50, 50, paint);
```

4. **Using ShapeDrawable**

=> ShapeDrawable can draw primitive shapes programmatically.

```java
ShapeDrawable shape = new ShapeDrawable(new OvalShape());
shape.getPaint().setColor(Color.BLUE);
shape.setBounds(50, 50, 250, 250);
shape.draw(canvas);
```

### Conclusion

=> Android 2D graphics can be created using XML drawables for simple shapes and Canvas/Paint/custom View for complex drawings.

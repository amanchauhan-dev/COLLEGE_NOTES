## Q.1 (a) What is the use of string.xml? [03]

=> `strings.xml` is a resource file stored in `res/values/strings.xml`.

=> It is used to store text values separately from Java/Kotlin and layout files.

### Uses

1. Avoids hardcoded strings in layout and code.
2. Makes text easy to change from one place.
3. Supports localization for multiple languages.
4. Improves code readability and maintenance.

### Example

```xml
<resources>
    <string name="app_name">My App</string>
    <string name="login">Login</string>
</resources>
```

Use in layout:

```xml
android:text="@string/login"
```

## Q.1 (c) Explain the activity life cycle in Android with example. [07]

=> Activity lifecycle is the sequence of states through which an Activity passes from creation to destruction.

### Diagram

```text
onCreate() -> onStart() -> onResume()
                    |
              Activity Running
                    |
                onPause()
               /        \
        onResume()     onStop()
                          |
                    onRestart()
                          |
                      onStart()

Finish: onPause() -> onStop() -> onDestroy()
```

### Methods

1. `onCreate()` - initializes Activity and layout.
2. `onStart()` - Activity becomes visible.
3. `onResume()` - Activity starts interacting with user.
4. `onPause()` - Activity loses focus.
5. `onStop()` - Activity becomes invisible.
6. `onRestart()` - stopped Activity starts again.
7. `onDestroy()` - Activity is destroyed.

### Example

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
    }

    @Override protected void onStart() { super.onStart(); }
    @Override protected void onResume() { super.onResume(); }
    @Override protected void onPause() { super.onPause(); }
    @Override protected void onStop() { super.onStop(); }
    @Override protected void onDestroy() { super.onDestroy(); }
}
```

## Q.2 (b) What are fragments? Explain fragments life cycle. [04]

=> Fragment is a reusable part of an Activity UI. It has its own lifecycle and must be hosted in an Activity.

### Fragment lifecycle

1. `onAttach()` - fragment attached to Activity.
2. `onCreate()` - fragment initialized.
3. `onCreateView()` - creates fragment UI.
4. `onActivityCreated()` - Activity creation completed.
5. `onStart()` - fragment becomes visible.
6. `onResume()` - fragment becomes interactive.
7. `onPause()` - fragment is no longer interactive.
8. `onStop()` - fragment is no longer visible.
9. `onDestroyView()` - fragment view destroyed.
10. `onDestroy()` - fragment destroyed.
11. `onDetach()` - fragment detached from Activity.

=> Fragments help create flexible and reusable UI.

```xml
    </TableRow>

            android:id="@+id/txtResult"
            android:textSize="20sp" />
    </TableRow>
```

### MainActivity.java

```java
public class MainActivity extends AppCompatActivity {
    EditText edtNum1, edtNum2;
    TextView txtResult;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        edtNum1 = findViewById(R.id.edtNum1);
        edtNum2 = findViewById(R.id.edtNum2);
        txtResult = findViewById(R.id.txtResult);

        findViewById(R.id.btnAdd).setOnClickListener(v -> calculate("+"));
        findViewById(R.id.btnSub).setOnClickListener(v -> calculate("-"));
        findViewById(R.id.btnMul).setOnClickListener(v -> calculate("*"));
        findViewById(R.id.btnDiv).setOnClickListener(v -> calculate("/"));
    }

    private void calculate(String op) {
        double a = Double.parseDouble(edtNum1.getText().toString());
        double b = Double.parseDouble(edtNum2.getText().toString());
        double result = 0;

        if (op.equals("+")) result = a + b;
        else if (op.equals("-")) result = a - b;
        else if (op.equals("*")) result = a * b;
        else if (op.equals("/")) result = a / b;

        txtResult.setText(String.valueOf(result));
    }
}
```

```xml
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"

        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:textSize="20sp" />
</LinearLayout>
```

### MainActivity.java

```java
public class MainActivity extends AppCompatActivity {
    TextView txtDob, txtCurrent, txtAge;
    Calendar dob = Calendar.getInstance();
    Calendar current = Calendar.getInstance();

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        txtDob = findViewById(R.id.txtDob);
        txtCurrent = findViewById(R.id.txtCurrent);
        txtAge = findViewById(R.id.txtAge);

        findViewById(R.id.btnDob).setOnClickListener(v -> showDatePicker(dob, txtDob));
        findViewById(R.id.btnCurrent).setOnClickListener(v -> showDatePicker(current, txtCurrent));

        findViewById(R.id.btnCalculate).setOnClickListener(v -> {
            int age = current.get(Calendar.YEAR) - dob.get(Calendar.YEAR);

            if (current.get(Calendar.DAY_OF_YEAR) < dob.get(Calendar.DAY_OF_YEAR)) {
                age--;
            }

            txtAge.setText("Your Age : " + age);
        });
    }

    private void showDatePicker(Calendar calendar, TextView textView) {
        new DatePickerDialog(this, (view, year, month, dayOfMonth) -> {
            calendar.set(year, month, dayOfMonth);
            textView.setText(dayOfMonth + "-" + (month + 1) + "-" + year);
        }, calendar.get(Calendar.YEAR),
                calendar.get(Calendar.MONTH),
                calendar.get(Calendar.DAY_OF_MONTH)).show();
    }
}
```

## Q.4 (c) Create a user registration application that stores the user details in a SQLite database table. [07]

### DBHelper.java

```java
public class DBHelper extends SQLiteOpenHelper {
    public DBHelper(Context context) {
        super(context, "UserDB", null, 1);
    }

    @Override
    public void onCreate(SQLiteDatabase db) {
        db.execSQL("CREATE TABLE users(" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT," +
                "name TEXT," +
                "email TEXT," +
                "password TEXT)");
    }

    @Override
    public void onUpgrade(SQLiteDatabase db, int oldVersion, int newVersion) {
        db.execSQL("DROP TABLE IF EXISTS users");
        onCreate(db);
    }

    public boolean insertUser(String name, String email, String password) {
        SQLiteDatabase db = getWritableDatabase();
        ContentValues values = new ContentValues();
        values.put("name", name);
        values.put("email", email);
        values.put("password", password);

        long result = db.insert("users", null, values);
        return result != -1;
    }
}
```

## Q.4 (c) OR Develop an alarm application that rings every Monday at 8 AM. [07]

### AndroidManifest.xml

```xml
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />

<application>
    <receiver android:name=".AlarmReceiver" />
</application>
```

### MainActivity.java

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        Calendar calendar = Calendar.getInstance();
        calendar.set(Calendar.DAY_OF_WEEK, Calendar.MONDAY);
        calendar.set(Calendar.HOUR_OF_DAY, 8);
        calendar.set(Calendar.MINUTE, 0);
        calendar.set(Calendar.SECOND, 0);

        if (calendar.getTimeInMillis() < System.currentTimeMillis()) {
            calendar.add(Calendar.WEEK_OF_YEAR, 1);
        }

        Intent intent = new Intent(this, AlarmReceiver.class);
        PendingIntent pendingIntent = PendingIntent.getBroadcast(
                this, 1, intent, PendingIntent.FLAG_IMMUTABLE);

        AlarmManager alarmManager =
                (AlarmManager) getSystemService(ALARM_SERVICE);

        alarmManager.setRepeating(
                AlarmManager.RTC_WAKEUP,
                calendar.getTimeInMillis(),
                AlarmManager.INTERVAL_DAY * 7,
                pendingIntent);
    }
}
```

### AlarmReceiver.java

```java
public class AlarmReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {
        MediaPlayer player = MediaPlayer.create(context, R.raw.alarm);
        player.start();

        Toast.makeText(context, "Monday 8 AM Alarm", Toast.LENGTH_LONG).show();
    }
}
```

```java
public class MainActivity extends AppCompatActivity {
    TextView txtLocation;
    LocationManager locationManager;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        txtLocation = new TextView(this);
        txtLocation.setTextSize(20);
        setContentView(txtLocation);

        locationManager = (LocationManager) getSystemService(LOCATION_SERVICE);

        if (ActivityCompat.checkSelfPermission(this,
                Manifest.permission.ACCESS_FINE_LOCATION)
                != PackageManager.PERMISSION_GRANTED) {
            ActivityCompat.requestPermissions(this,
                    new String[]{Manifest.permission.ACCESS_FINE_LOCATION}, 1);
            return;
        }

        locationManager.requestLocationUpdates(
                LocationManager.GPS_PROVIDER,
                5000,
                5,
                location -> {
                    double lat = location.getLatitude();
                    double lng = location.getLongitude();
                    txtLocation.setText("Latitude: " + lat + "\nLongitude: " + lng);
                });
    }
}
```

## Q.5 (c) OR Explain the challenges when we use the location based services. [07]

=> Location-based services use GPS, network and sensors to determine user location.

### Challenges

1. **Battery consumption**

=> GPS continuously consumes more battery.

2. **Accuracy**

=> GPS may be inaccurate indoors or in crowded areas.

3. **Network dependency**

=> Network provider requires mobile network or Wi-Fi.

4. **Permission handling**

=> Apps must request location permissions and handle denial properly.

5. **Privacy**

=> Location is sensitive data and must be used carefully.

6. **Provider availability**

=> GPS or location services may be disabled by user.

7. **Latency**

=> Getting first location fix can take time.

8. **Background restrictions**

=> New Android versions restrict background location access.

### Solutions

1. Request location only when needed.
2. Use appropriate accuracy level.
3. Stop location updates after use.
4. Explain permission need clearly to user.
5. Use fused location provider for better efficiency.

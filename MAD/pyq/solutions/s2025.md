## Q.1 (a) Describe DVM in Android. [03]

=> **DVM** stands for **Dalvik Virtual Machine**.

=> It is the virtual machine traditionally used by Android to execute Android applications.

=> Android applications are generally written in Java and compiled into `.class` files first. These class files are then converted into `.dex` files using Android SDK tools. The `.dex` file is executed by the Dalvik Virtual Machine.

### Important points

1. DVM is optimized for mobile devices with limited memory, battery and CPU power.
2. Each Android application runs in its own Linux process with its own DVM instance.
3. It executes Dalvik bytecode, not normal Java bytecode directly.
4. It provides security because applications run separately from each other.
5. It supports multitasking by allowing multiple DVM instances to run at the same time.

=> Thus, DVM is an important part of Android runtime that helps Android apps run efficiently on mobile devices.

## Q.1 (b) List and explain Android application components. [04]

=> Android application components are the essential building blocks of an Android application.

### Main application components

1. **Activity**

=> An Activity represents a single screen with a user interface.

=> Example: Login screen, registration screen, home screen.

2. **Service**

=> A Service performs long-running work in the background without a user interface.

=> Example: Playing music, downloading a file, syncing data.

=> Example: Contacts provider shares contact information with other apps.

=> These components are declared in the `AndroidManifest.xml` file, which tells Android how the application is structured.

## Q.1 (c) What is Activity? Draw and explain Activity lifecycle in detail. [07]

=> **Definition**: `An Activity is an Android application component that represents one screen of the application and provides a user interface for user interaction.`

=> An application may contain one or more activities. Each activity has its own lifecycle methods that are called automatically by the Android system.

### Activity lifecycle diagram

```text
Activity launched
      |
      v
  onCreate()
      |
      v
  onStart()
      |
      v
  onResume()
      |
      v
Activity running
      |
      v
  onPause()
   /      \
  v        v
onResume() onStop()
             |
             v
        onRestart()
             |
             v
          onStart()
             |
             v
          onResume()

If activity is finished:
onPause() -> onStop() -> onDestroy()
```

### Lifecycle methods

1. **onCreate()**

=> Called when the activity is first created.

=> It is used to initialize variables, create views and call `setContentView()`.

2. **onStart()**

=> Called when the activity becomes visible to the user.

3. **onResume()**

=> Called when the activity starts interacting with the user.

=> At this stage, the activity is in the foreground.

4. **onPause()**

=> Called when another activity comes in front and the current activity loses focus.

=> It is used to pause animations, stop camera preview or save small temporary changes.

5. **onStop()**

=> Called when the activity is no longer visible to the user.

6. **onRestart()**

=> Called when the stopped activity is started again.

7. **onDestroy()**

=> Called before the activity is destroyed.

=> It is used to release resources.

### Example

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
    }

    @Override
    protected void onStart() {
        super.onStart();
    }

    @Override
    protected void onResume() {
        super.onResume();
    }

    @Override
    protected void onPause() {
        super.onPause();
    }

    @Override
    protected void onStop() {
        super.onStop();
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
    }
}
```

## Q.2 (b) What is AVD? How to create AVD in Android Studio? [04]

=> **AVD** stands for **Android Virtual Device**.

=> It is a configuration that defines the characteristics of a virtual Android phone, tablet, TV or wearable device.

=> AVD works with the Android Emulator and allows developers to run and test Android applications without a physical device.

### AVD contains

1. Hardware profile.
2. System image.
3. Storage area.
4. Screen size and resolution.
5. Android version and emulator settings.

### Steps to create AVD in Android Studio

1. Open **Android Studio**.
2. Go to **Tools -> Device Manager**.
3. Click **Create Device**.
4. Select a hardware profile, such as Pixel phone or tablet.
5. Click **Next**.
6. Select and download the required Android system image.
7. Click **Next**.
8. Configure device name, orientation and advanced settings if required.
9. Click **Finish**.
10. Start the emulator by clicking the **Run/Play** button.

=> Now the application can be installed and tested on the created virtual device.

## Q.2 (c) What is an Intent? Explain types of Intent in Android with example. [07]

=> **Definition**: `An Intent is a messaging object used to request an action from another Android application component.`

=> Intents are used to start activities, start services, deliver broadcasts and pass data between components.

### Uses of Intent

1. Start a new Activity.
2. Start a Service.
3. Send a Broadcast.
4. Pass data using extras.
5. Open another application component such as browser, dialer or camera.

### Types of Intent

1. **Explicit Intent**

=> Explicit Intent specifies the exact component to start by giving the class name.

=> It is mostly used to move from one activity to another activity inside the same application.

```java
Intent intent = new Intent(MainActivity.this, SecondActivity.class);
intent.putExtra("username", "Aman");
startActivity(intent);
```

Receiving data in second activity:

```java
Intent intent = getIntent();
String name = intent.getStringExtra("username");
```

2. **Implicit Intent**

=> Implicit Intent does not specify the exact component. It only declares the action to perform.

=> Android searches for an application that can handle that action.

Example: Open dialer

```java
Intent intent = new Intent(Intent.ACTION_DIAL);
intent.setData(Uri.parse("tel:9876543210"));
startActivity(intent);
```

Example: Open web page

```java
Intent intent = new Intent(Intent.ACTION_VIEW);
intent.setData(Uri.parse("https://www.google.com"));
startActivity(intent);
```

### Difference between explicit and implicit intent

| Explicit Intent | Implicit Intent |
|---|---|
| Specifies target component directly. | Does not specify target component. |
| Used within same app mostly. | Used to call system or other app components. |
| Example: Open `SecondActivity`. | Example: Open browser or dialer. |

## Q.3 (b) Explain how screen orientation is managed in Android. [04]

=> Screen orientation means changing the display between **portrait** and **landscape** mode.

=> Android automatically destroys and recreates the current activity when orientation changes. This allows Android to load suitable resources for the new configuration.

### Ways to manage orientation

1. **Using layout folders**

=> Keep portrait layout in:

```text
res/layout/activity_main.xml
```

=> Keep landscape layout in:

```text
res/layout-land/activity_main.xml
```

=> Android automatically loads the correct layout.

2. **Saving state**

=> Use `onSaveInstanceState()` to save temporary data before orientation changes.

```java
@Override
protected void onSaveInstanceState(Bundle outState) {
    super.onSaveInstanceState(outState);
    outState.putString("name", "Aman");
}
```

3. **Restoring state**

```java
if (savedInstanceState != null) {
    String name = savedInstanceState.getString("name");
}
```

4. **Fixing orientation**

=> Orientation can be fixed in `AndroidManifest.xml`.

```xml
<activity
    android:name=".MainActivity"
    android:screenOrientation="portrait" />
```

5. **Handling configuration manually**

=> Developer can use `android:configChanges`, but it should be used carefully.

```java
public class MyAdapter extends RecyclerView.Adapter<MyAdapter.MyViewHolder> {
    String[] names;

    public MyAdapter(String[] names) {
        this.names = names;
    }

    public static class MyViewHolder extends RecyclerView.ViewHolder {
        TextView txtName;

        public MyViewHolder(View itemView) {
            super(itemView);
            txtName = itemView.findViewById(R.id.txtName);
        }
    }

    @Override
    public MyViewHolder onCreateViewHolder(ViewGroup parent, int viewType) {
        View view = LayoutInflater.from(parent.getContext())
                .inflate(R.layout.row_item, parent, false);
        return new MyViewHolder(view);
    }

    @Override
    public void onBindViewHolder(MyViewHolder holder, int position) {
        holder.txtName.setText(names[position]);
    }

    @Override
    public int getItemCount() {
        return names.length;
    }
}
```

## Q.4 (b) Explain geocoding and reverse geocoding in Android. [04]

### Geocoding

=> **Geocoding** is the process of converting a text address or place name into latitude and longitude coordinates.

=> Example: Converting `"Ahmedabad, Gujarat"` into coordinates.

=> **Reverse geocoding** is the process of converting latitude and longitude into a readable address.

=> Example: Converting coordinates into city, state, country and postal code.

```java
Geocoder geocoder = new Geocoder(this);
List<Address> list = geocoder.getFromLocation(23.0225, 72.5714, 1);

if (!list.isEmpty()) {
    String address = list.get(0).getAddressLine(0);
}
```

### Difference

| Geocoding | Reverse Geocoding |
|---|---|
| Address to latitude/longitude. | Latitude/longitude to address. |
| Input is place name or address. | Input is coordinates. |
| Example: Ahmedabad -> coordinates. | Example: coordinates -> Ahmedabad. |

## Q.4 (c) Explain SQLite database using appropriate example. [07]

=> **SQLite** is a lightweight relational database used in Android for storing structured data persistently.

=> It is built into Android, so no separate installation or server is required.

### Features

1. Lightweight database.
2. Requires very little memory.
3. Supports SQL statements.
4. Stores data persistently.
5. Useful for structured data like student records, contacts and notes.

### SQLiteOpenHelper

=> Android uses `SQLiteOpenHelper` to create and manage databases.

### DBHelper.java

```java
public class DBHelper extends SQLiteOpenHelper {
    public static final String DB_NAME = "StudentDB";
    public static final int DB_VERSION = 1;

    public DBHelper(Context context) {
        super(context, DB_NAME, null, DB_VERSION);
    }

    @Override
    public void onCreate(SQLiteDatabase db) {
        db.execSQL("CREATE TABLE student(" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT," +
                "name TEXT," +
                "branch TEXT)");
    }

    @Override
    public void onUpgrade(SQLiteDatabase db, int oldVersion, int newVersion) {
        db.execSQL("DROP TABLE IF EXISTS student");
        onCreate(db);
    }

    public boolean insertStudent(String name, String branch) {
        SQLiteDatabase db = getWritableDatabase();

        ContentValues values = new ContentValues();
        values.put("name", name);
        values.put("branch", branch);

        long result = db.insert("student", null, values);
        return result != -1;
    }
}
```

### Using DBHelper in Activity

```java
DBHelper dbHelper = new DBHelper(this);
boolean inserted = dbHelper.insertStudent("Aman", "Computer");

if (inserted) {
    Toast.makeText(this, "Data inserted", Toast.LENGTH_SHORT).show();
} else {
    Toast.makeText(this, "Insert failed", Toast.LENGTH_SHORT).show();
}
```

### SQLite operations

1. `insert()` inserts new records.
2. `query()` or `rawQuery()` reads records.
3. `update()` updates records.
4. `delete()` deletes records.

## Q.4 (c) OR Write code to insert Student Details (enrollment, name, branch) in SQLite Database in Android. [07]

### DBHelper.java

```java
package com.example.studentdb;

import android.content.ContentValues;
import android.content.Context;
import android.database.sqlite.SQLiteDatabase;
import android.database.sqlite.SQLiteOpenHelper;

public class DBHelper extends SQLiteOpenHelper {
    private static final String DB_NAME = "StudentDB";
    private static final int DB_VERSION = 1;
    private static final String TABLE_NAME = "student";

    public DBHelper(Context context) {
        super(context, DB_NAME, null, DB_VERSION);
    }

    @Override
    public void onCreate(SQLiteDatabase db) {
        String query = "CREATE TABLE " + TABLE_NAME + "("
                + "enrollment TEXT PRIMARY KEY,"
                + "name TEXT,"
                + "branch TEXT)";
        db.execSQL(query);
    }

    @Override
    public void onUpgrade(SQLiteDatabase db, int oldVersion, int newVersion) {
        db.execSQL("DROP TABLE IF EXISTS " + TABLE_NAME);
        onCreate(db);
    }

    public boolean insertStudent(String enrollment, String name, String branch) {
        SQLiteDatabase db = this.getWritableDatabase();

        ContentValues values = new ContentValues();
        values.put("enrollment", enrollment);
        values.put("name", name);
        values.put("branch", branch);

        long result = db.insert(TABLE_NAME, null, values);
        db.close();

        return result != -1;
    }
}
```

```java
package com.example.mediaplayerdemo;

import android.media.MediaPlayer;
import android.os.Bundle;
import android.widget.Button;
import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {
    MediaPlayer mediaPlayer;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        Button btnPlay = findViewById(R.id.btnPlay);
        Button btnPause = findViewById(R.id.btnPause);
        Button btnStop = findViewById(R.id.btnStop);

        mediaPlayer = MediaPlayer.create(this, R.raw.song);

        btnPlay.setOnClickListener(v -> mediaPlayer.start());

        btnPause.setOnClickListener(v -> {
            if (mediaPlayer.isPlaying()) {
                mediaPlayer.pause();
            }
        });

        btnStop.setOnClickListener(v -> {
            if (mediaPlayer != null) {
                mediaPlayer.stop();
                mediaPlayer.release();
                mediaPlayer = MediaPlayer.create(this, R.raw.song);
            }
        });
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        if (mediaPlayer != null) {
            mediaPlayer.release();
            mediaPlayer = null;
        }
    }
}
```

### Advantages

1. Supports audio and video playback.
2. Can play local and network files.
3. Provides methods like `start()`, `pause()`, `stop()` and `release()`.
4. Useful for music players, video players and sound-based apps.

## Q.5 (b) OR Discuss Services in Android. [04]

=> **Service** is an Android application component used to perform long-running operations in the background without a user interface.

### Uses

1. Playing music in background.
2. Downloading files.
3. Uploading data.
4. Syncing data with server.
5. Tracking location.

### Types of Services

1. **Started Service**

=> Started using `startService()`.

=> It runs in background even if the starting component is destroyed.

2. **Bound Service**

=> Bound using `bindService()`.

=> It allows components to interact with the service.

3. **Foreground Service**

=> Performs work visible to the user and shows a notification.

=> Example: Music player or location tracking.

### Service lifecycle

2. `onStartCommand()` - Service starts work.
3. `onBind()` - Used for bound service.

```java
    }

        return null;
    }
}
```

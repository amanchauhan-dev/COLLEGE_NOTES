## Q.1 (c) Explain Water Jug Problem with example. [07]

=> The **water jug problem** is a state space search problem where we measure exact water using jugs of fixed capacity.

### Example

Two jugs are given:

```text
8-liter jug and 5-liter jug
Goal: get exactly 4 liters in 8-liter jug
```

### State representation

```text
(x, y)
```

Where `x` is water in 8-liter jug and `y` is water in 5-liter jug.

### Operators

1. Fill 8-liter jug
2. Fill 5-liter jug
3. Empty 8-liter jug
4. Empty 5-liter jug
5. Pour 8-liter jug into 5-liter jug
6. Pour 5-liter jug into 8-liter jug

### Solution path

```text
(0,0) -> (0,5) -> (5,0) -> (5,5) -> (8,2)
-> (0,2) -> (2,0) -> (2,5) -> (7,0)
-> (7,5) -> (8,4) -> (0,4) -> (4,0)
```

=> Final state is `(4,0)`, so the 8-liter jug contains exactly 4 liters.

=> A state better than all neighboring states but not the best global solution.

2. **Plateau**

=> A flat region where all neighboring states have the same heuristic value.

3. **Ridge**

=> A narrow path where progress requires indirect or sideways moves.

## Q.2 (b) Explain Best First Search with suitable example. [04]

=> **Best First Search** expands the most promising node first using a heuristic function.

### Algorithm

```text
1. Put start node in OPEN list.
2. Select node with best heuristic value.
3. If it is goal, stop.
4. Expand it and add successors to OPEN.
5. Put expanded node in CLOSED.
6. Repeat.
```

### Example

If heuristic values are:

```text
A -> B = 6
A -> C = 3
A -> D = 8
```

Best first search selects `C` first because it has the lowest heuristic value.

### Advantages

1. Faster than blind search when heuristic is good.
2. Avoids expanding many unnecessary nodes.

## Q.2 (c) Explain A* algorithm. What happens if h' underestimates h and overestimates h? [07]

=> **A* algorithm** is an informed search algorithm that combines path cost and heuristic cost.

### Evaluation function

```text
f(n) = g(n) + h'(n)
```

Where:

1. `g(n)` = actual cost from start to node `n`
2. `h'(n)` = estimated cost from node `n` to goal
3. `f(n)` = estimated total cost of solution path

### Algorithm

```text
1. Put start node in OPEN.
2. Compute f(n) = g(n) + h'(n).
3. Select node with minimum f(n).
4. If selected node is goal, return path.
5. Otherwise expand it.
6. Update OPEN and CLOSED lists.
7. Repeat until goal is found.
```

### Effect of heuristic

1. **If h' underestimates h**

=> A* is admissible and gives optimal solution, but may expand more nodes.

2. **If h' equals h**

=> A* finds optimal path very efficiently.

3. **If h' overestimates h**

=> A* may become faster, but optimality is not guaranteed.

## Q.2 (c) OR Define constraint satisfaction problem (CSP). How CSP is formulated as a search problem? [07]

=> A **Constraint Satisfaction Problem** is a problem where a solution must satisfy a set of constraints.

### Components

1. **Variables**

=> Unknowns to be assigned values.

2. **Domains**

=> Possible values for variables.

3. **Constraints**

=> Rules that restrict valid combinations of values.

### Example

Map coloring:

```text
Variables: states/regions
Domain: red, green, blue
Constraint: neighboring regions must have different colors
```

### CSP as search problem

1. **Initial state**

=> No variable is assigned.

2. **Actions**

=> Assign a value to an unassigned variable.

3. **Transition model**

=> Produces a new partial assignment.

4. **Goal test**

=> All variables are assigned and all constraints are satisfied.

5. **Path cost**

=> Usually constant or not important.

## Q.3 (c) Explain Forward and Backward Chaining with example. [07]

### Forward chaining

=> Forward chaining is data-driven reasoning. It starts from known facts and applies rules to derive new facts.

Example:

```text
Fact: Fever
Fact: Cough
Rule: Fever and Cough -> Flu
Conclusion: Flu
```

### Algorithm

```text
1. Start with known facts.
2. Find rules whose conditions are true.
3. Add their conclusions to knowledge base.
4. Repeat until goal is derived or no rule applies.
```

### Backward chaining

=> Backward chaining is goal-driven reasoning. It starts from the goal and works backward to prove required facts.

Example:

```text
Goal: Flu
Rule: Fever and Cough -> Flu
Subgoals: Fever, Cough
If both are facts, Flu is proved.
```

### Difference

| Forward chaining | Backward chaining |
|---|---|
| Data-driven | Goal-driven |
| Starts with facts | Starts with goal |
| Useful when many conclusions are needed | Useful when specific query is given |

## Q.3 (b) OR Describe the axioms of probability theory. [04]

1. **Non-negativity**

```text
P(A) >= 0
```

2. **Normalization**

```text
P(True) = 1
```

3. **Additivity**

If A and B are mutually exclusive:

```text
P(A or B) = P(A) + P(B)
```

4. **Complement rule**

```text
P(not A) = 1 - P(A)
```

## Q.4 (c) Discuss Iterative Deepening search. [07]

=> **Iterative Deepening Search** repeatedly applies depth-limited search with increasing depth limits.

### Algorithm

```text
for depth = 0 to infinity:
    perform depth limited search up to depth
    if goal found, return solution
```

### Working

```text
Depth 0: search root
Depth 1: search root and children
Depth 2: search root, children and grandchildren
...
```

### Advantages

1. Complete like BFS.
2. Uses low memory like DFS.
3. Finds shallowest solution.
4. Useful when solution depth is unknown.

### Disadvantage

=> Some upper-level nodes are generated repeatedly.

## Q.4 (b) OR Explain the fail and cut predicate in Prolog with an example. [04]

### Cut predicate `!`

=> Cut prevents Prolog from backtracking beyond that point.

```prolog
max(A, B, A) :-
    A >= B, !.
max(A, B, B).
```

### Fail predicate

=> `fail` always fails and forces backtracking.

```prolog
print_list([]).
print_list([H|T]) :-
    write(H), nl,
    fail.
print_list(_).
```

=> Cut controls backtracking, while fail forces backtracking.

## Q.5 (a) Discuss Bayes theorem. [03]

=> **Bayes theorem** is used to calculate posterior probability using prior probability and evidence.

### Formula

```text
P(H | E) = P(E | H) P(H) / P(E)
```

Where:

1. `P(H | E)` = posterior probability
2. `P(H)` = prior probability
3. `P(E | H)` = likelihood
4. `P(E)` = evidence probability

## Q.5 (c) Explain the MiniMax procedure in a two-player game with an appropriate example. [07]

=> **Minimax** is used in two-player games to select the best move assuming both players play optimally.

### Algorithm

```text
1. Generate game tree.
2. Assign utility values to leaf nodes.
3. MAX chooses maximum value.
4. MIN chooses minimum value.
5. Back up values to root.
6. Select move with best value for MAX.
```

### Example

```text
          MAX
        /     \
      MIN     MIN
     /  \     /  \
    4    7   2    9
```

MIN values:

```text
min(4,7) = 4
min(2,9) = 2
```

MAX value:

```text
max(4,2) = 4
```

=> MAX selects the left branch.
